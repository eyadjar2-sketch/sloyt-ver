# Культурный слой Твери — сайт для GitHub Pages

Это статический сайт для размещения на GitHub Pages. В архив уже входят страница, данные, фотографии, логотип, MapLibre GL JS, Three.js, workflow публикации и русскоязычное описание проекта с речью для защиты (`PROJECT_DESCRIPTION_RU.md`). Node.js, сервер, база данных и отдельный API-ключ владельца для запуска сайта не нужны.

## Как загрузить ZIP в GitHub

1. В GitHub создайте публичный репозиторий для сайта. Если репозиторий уже создан, откройте его.
2. Скачайте ZIP проекта и распакуйте его на компьютере. Важно: откройте получившуюся папку и выделите **всё содержимое**, включая скрытую папку `.github` и файл `.gitignore`.
3. Загрузите это содержимое в корень репозитория. Правильная структура выглядит так: `README.md`, `.github/workflows/pages.yml` и `public/index.html`. Не кладите всё внутрь дополнительной папки, например `kulturny/`.
4. Добавьте файлы в ветку `main`, создайте commit и нажмите **Push/Sync**. Через обычный браузер GitHub иногда скрытые файлы неудобно загружать; если папки `.github` не видно, используйте Codespaces или GitHub Desktop.
5. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Сохраните настройку, если GitHub показывает кнопку сохранения.
6. Перейдите во вкладку **Actions**. Откройте запуск **Deploy to GitHub Pages** и дождитесь зелёного статуса **Success**.
7. Вернитесь в **Settings → Pages**. Там появится адрес сайта. Для репозитория `имя-проекта` он обычно выглядит как `https://имя-пользователя.github.io/имя-проекта/`.

В дальнейшем для обновления сайта внесите изменения в файлы, затем выполните из корня репозитория:

```sh
git add .
git commit -m "Обновить сайт"
git push origin main
```

Если команда `git push` сообщает, что на GitHub уже есть новые коммиты, не используйте `git push --force`. Сначала выполните `git fetch origin` и аккуратно объедините новые изменения с вашей веткой. В Codespaces это можно сделать в терминале или через Source Control.

## Просмотр сайта до загрузки

Из корня проекта запустите локальный веб-сервер:

```sh
python3 -m http.server 8000 --directory public
```

Затем откройте `http://localhost:8000`. Не открывайте `index.html` двойным щелчком через `file://`: для локального JSON и JavaScript-модулей нужен сервер.

## Как работает карта

На странице одна цветная карта на MapLibre GL JS со стилем OpenFreeMap Bright. Для типов мест используются разные SVG-значки, близкие точки собираются в счётные кластеры, а нажатие на значок открывает прямо на карте панель с фотографией, названием, краткой информацией и ссылками. Подложка и векторные данные загружаются с публичного сервиса [OpenFreeMap](https://openfreemap.org/) по интернету; отдельный API-ключ не требуется. Передвигать карту можно только в пределах заданной области Твери; автоматически проложенной линии маршрута нет. Компактная атрибуция OpenMapTiles/OpenStreetMap отображается внутри самой карты и не вынесена в отдельную нижнюю панель.

MapLibre GL JS и Three.js уже лежат в `public/assets/vendor/`; фотографии и эмблема также хранятся локально. В монастырских карточках сначала показан исторический вид, затем современная фотография; на карте порядок тот же. 3D-объекты — схематические модели, а не точные реконструкции. В разделе экскурсий есть демонстрационная форма записи и место для контактов. Форма пока не отправляет заявки, поскольку реальные контакты проекта ещё не указаны. Аудиоплеер выключен: записей в проекте пока нет. Google Fonts и карта требуют подключения к интернету; при отсутствии сети шрифты заменяются резервными.
